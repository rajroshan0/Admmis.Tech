# Plan — T-404 / T-406 CMS collections and migrations-at-start
Owner: neha · Date: 2026-11-07 · Due: T-404 today, T-406 Thu 12 Nov · Reviewer: hritik

## 1. Goal
Editors can manage pages, services, rent pages, prices and media in Payload with least-privilege access, no price exposed except through the `pricing` source, and a migration setup that runs at app start (ADR-032). Soft launch is Mon 14 Dec, so this is pulled forward.

## 2. Inputs I read
`docs/api/content-model.md` v0.2, ADR-025..029, ADR-032, `design/templates/service-spec.md` §5 and `rent-spec.md` §5, current `src/payload.config.ts`, `Users.ts`, `Media.ts`.

## 3. Approach (decisions for hritik)
1. **Migrations at start (ADR-032).** `postgresAdapter({ prodMigrations: migrations })` with `migrations` from `src/migrations/index.ts` (generated by `payload migrate:create`). Payload runs pending migrations on init when `NODE_ENV=production`; dev keeps `push` (no files needed while iterating). Rule: every schema change ships a reviewed migration; CI fails if `payload migrate:status` shows drift is not possible without DB, so Raj adds a DB-backed CI step later.
2. **Service and rent pages use the designers' fixed fields**, not free `body` blocks (specs §5 are newer than content-model v0.2). Services get named groups (hero, facts, intro, types[], benefits[], steps[], detail, price, crossSell[], faqs, form). `pages` keeps `blocks` for home/about/legal etc. and gets template-conditional groups for `rent-hub` and `rent-product`. I will update content-model to v0.3 (ADR-029 rental split, `rentalPlans`, fixed service fields).
3. **`rentalPlans` collection** (band, label, forWho, `priceRef` -> `pricing`, setupText, inclusions[], supportText, quoteOnly, product). Plan without a published price: page renders "price on request" and the editor sees a warning (rent-spec).
4. **Prices:** `pricing` is the only collection with amounts. Create/update admin only (ADR-025); editors and sales read. Public REST/GraphQL off for content; frontend reads via local API server-side. Spec says prices are public on the site, so ADR-025 means admin-only *editing*, not hidden display.
5. **CMS maxLength = EN x 1.4** from the specs, applied per field. Arrays use `minRows`/`maxRows` from the specs. Required means required to publish (drafts may be incomplete, via `versions.drafts` validate only on publish).
6. **Shared pieces:** `fields/seo.ts`, `fields/cta.ts`, `access/*.ts` (isAdmin, isEditorOrAdmin, isSalesOrAdmin), slug lock hook, revalidate hook (stub calling `src/lib/server/revalidate.ts`, tags per content-model §1). Globals: `siteSettings` (header, footer, contacts, announcement, stickyBar), no secrets.
7. Icon fields use Satish's 21-name list (component-inventory §2); I import it from one `src/collections/fields/icons.ts` to keep a single list.
8. Out of this task: leads, leadJobs, cases, posts, jobs, events (T-4xx later). `users.role` stays `roles` as in the scaffold (note: content-model says `role`; I keep scaffold name and fix the doc).
