## 3. Approach (decisions I will put in the doc)
1. **Locale scheme CONFIRMED, no change:** EN unprefixed at root, NE under `/ne/`, one shared English slug, no Devanagari in URLs. `/en/...` 308-redirects to the unprefixed URL. EN is the `x-default`. Alternative rejected: always-prefix `/en/` (symmetry is not worth changing printed/shared URLs such as `/opening-event`).
2. **Library: next-intl** with `localePrefix: 'as-needed'` and `localeDetection: false`. Reasons: maintained for App Router, static rendering support, ICU plurals, `Intl` formatting helpers, typed keys, and `as-needed` is exactly our scheme. Hand-rolled alternative (proxy rewrite + JSON loader + formatters) rejected: we would own plural/format code. Cost control: Server Components use server `getTranslations`; only namespaces a client island needs are sent to the client provider. Bundle impact measured at scaffold (bundle analyzer), not claimed now.
3. **No auto-detection redirect** by Accept-Language or cookie on content URLs (SEO, cache, and it would break the EN-unprefixed contract). Switcher is a plain link to the same path in the other locale.
4. **Enabling a locale = env + deploy:** `ENABLED_LOCALES` (default `en`) drives routing, `generateStaticParams`, hreflang, sitemap and the switcher. It is the single source of truth; I will ask Neha to make `siteSettings.localesEnabled` informational or remove it (a CMS checkbox cannot create static pages).
5. **Fallback rules:** CMS text: `ne` empty → `en` (Payload fallback). UI strings: per-key fallback to EN. SEO: an NE page appears in hreflang and sitemap only when fully translated (needs Neha's `translatedLocales` computed field); otherwise it is served with `noindex` and canonical to EN. CI check: every key in `en` exists in `ne` before NE is enabled.
6. **Messages:** `src/messages/<locale>/<namespace>.json`, loader merges per locale and falls back per key. What belongs in messages vs CMS is a table in the doc.
7. **Typography:** Devanagari via `next/font` with locale-specific font loading (EN pages must not download Devanagari), `:lang(ne)` line-height/letter-spacing rules (Satish owns tokens), `<html lang>` per locale.
8. **Formatting:** `Intl` for dates, numbers, currency (NPR, USD from integer minor units). Numerals and calendar (Bikram Sambat) are open questions for the February native review; defaults stated.
9. **Switch-on checklist** (numbered, with owners) and what must never be done (hard-coded strings, locale-specific layout, localized slugs).
